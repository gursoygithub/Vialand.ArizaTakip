## Shield (Permissions)

- Policies live in `app/Policies/`, bound in `AppServiceProvider`
- Permissions defined in `database/seeders/PermissionSeeder.php`

## Permission Architecture (post-reform — single source of truth)

**Three-layer permission model:**

**Layer 1 — Shield Resources (CRUD)**: `view_any_X`, `view_X`, `create_X`, `update_X`,
`delete_X`, `delete_any_X`. Auto-generated by `shield:generate`. Manage from "Kaynaklar"
tab in the role editor.

**Layer 2 — Shield Pages**: `page_X`. For Filament Page classes. Manage from "Sayfalar"
tab. `canAccess()` and `shouldRegisterNavigation()` both check `page_X` — consistent.
**Always match `canAccess()` to the `page_{ClassName}` permission** Shield generates,
not a custom domain permission.

**Layer 3 — Shield Widgets**: `widget_X`. For widget classes. `canView()` checks
`widget_X` on every widget.

**super_admin passes every permission check.** `config/filament-shield.php` sets
`super_admin.define_via_gate = true` (Gate::before), so a newly added permission
never locks super_admin out. Static `canEdit()` / `canDelete()` overrides that
return false without asking the gate still apply to super_admin.
In tests, grant the needed permissions explicitly (see `EmployeeCompanyDisplayTest`).

**Custom permissions (action-level + scope-bypass)**:

Action-level (gates buttons/operations inside a surface):
- `ticket.export` — PDF/Excel export (renamed from `report.view` in the May 2026 reform)
- `user.role.assign` — role assignment in `UserResource` + `CompanyAccessRelationManager`
- `view_tc_no` — TC number column visibility
- `create_custom_*` — inline create-on-the-fly in Select fields

Scope-bypass (default scope = `created_by`; permission removes the filter):
- `view_all_companies`, `view_all_areas`, `view_all_sub_areas`,
  `view_all_sla_policies`, `view_all_groups`, `view_all_group_members`,
  `view_all_units`, `view_all_employees`, `view_all_users`,
  `view_all_subcontractors`, `view_all_subcontractor_employees`

Ticket has its own scope mechanism (NOT `view_all_tickets`):
- `ticket.view.all` — bypass all scope (canonical; legacy `view_all_tasks` removed)

**Rule of thumb**:
- Shield = "Can the user reach this surface?" (page / widget / resource)
- Custom = "Once on the surface, can they do this specific thing?"
  OR "Should the created_by scope filter be bypassed?"

**Single source of truth for role assignments**: the Shield UI
(Roller > Düzenle > Kaynaklar / Sayfalar / Araçlar / Özel İzinler).
`PermissionSeeder` is existence-only — it guarantees permission/role rows exist and
syncs `super_admin` to all permissions, but makes NO grants to admin / supervisor /
manager / technician / viewer. Those are managed exclusively via the Shield UI.

### Resource Scope (non-Ticket)

All non-Ticket resources use the `ScopedByVisibility` trait
(`app/Filament/Concerns/ScopedByVisibility`). The trait:
- Default scope: `where('created_by', auth()->id())`
- Bypassed by per-resource `view_all_X` permission (set
  `protected static string $viewAllPermission`)
- super_admin bypasses via an explicit `hasRole('super_admin')` check in the trait
- For resources needing additional WHERE clauses, override `getEloquentQuery()`
  and call `static::applyVisibilityScope(parent::getEloquentQuery())`, then chain
  extra clauses (see `UserResource` for example)

## Commands — always use `sail` prefix (Docker environment)
The `sail` binary lives at `./vendor/bin/sail` (NOT in PATH). Use it directly:
```bash
./vendor/bin/sail artisan migrate     # run migrations
./vendor/bin/sail artisan route:list  # list routes
./vendor/bin/sail artisan test        # run tests
./vendor/bin/sail composer require .. # install packages
./vendor/bin/sail artisan queue:work  # start queue worker
```
Container name depends on the compose project directory — confirm with `docker ps`.
Tests use SQLite in-memory (configured in `phpunit.xml`).
**Run tests with PHP 8.4.** `composer.lock` requires PHP ≥ 8.4; the WSL host CLI
is PHP 8.3, so host runs die in Composer's platform check. Without starting the
stack, a one-off container works:
```bash
docker run --rm -u "$(id -u):$(id -g)" -v "$PWD":/var/www/html -w /var/www/html --entrypoint php sail-8.4/app vendor/bin/phpunit --testsuite Feature
```
Use `--testsuite Feature` (or `php artisan test --testsuite=Feature`): plain
`php artisan test` fails because `phpunit.xml` lists a `tests/Unit` directory that
does not exist. **Always pass `-u "$(id -u):$(id -g)"`** to one-off containers:
run as root, they create `storage/logs/laravel-YYYY-MM-DD.log` and compiled views
owned by root, and the local app then fails every request that logs (LdapRecord
logs each bind) with "could not be opened in append mode: Permission denied".
**Pint:** run it only on new files. Many existing files are not Pint-clean and are
stored with CRLF line endings; `pint --dirty` reformats whole files and buries the
real change (Altın Kural #1).

## Infrastructure (production)
- `docker-compose.prod.yml` bind-mounts the repo: `.:/var/www`. The image's
  `COPY`, `composer install` and `npm run build` are shadowed by the host
  checkout — host `vendor/` and `public/build` are what actually run.
  Changes under `/etc/php/...` (e.g. the `Dockerfile` php2shell mitigation
  `99-php2shell-mitigation.ini`) only take effect after an **image rebuild**.
- The repo's `php.ini` is **not** wired into the image on `gg-ticket`.
- `.docker/start.sh` runs `php artisan config:cache` on every start. With a cached
  config, `env()` called outside `config/` returns `null` (unless the variable is a
  real process env var). Affected: `AuthService::login` (local admin bypass via
  `APP_ADMIN_USERNAME`/`APP_ADMIN_PASSWORD`) and `User::query()` (hides the
  `APP_ADMIN_USERNAME` user, falls back to `'sa'`).
- Supervisor (`.docker/supervisord.conf`) runs php-fpm, nginx, `schedule:work`
  and 2× `queue:work` — scheduler and workers run as **root**, php-fpm as
  `www-data` (why the 23:55 schedule pre-creates tomorrow's log with `chmod 0777`).
  Inside the container use `supervisorctl -c /etc/supervisor/supervisord.conf status`
  (plain `supervisorctl` does not find the config).
- `.env.example` is a template from another project (fr locale, `Africa/Ndjamena`,
  DigitalOcean bucket) — it does not describe this app's real variables.

## Company Access

Users are scoped to one or more companies. The canonical helper is on the User model:

```php
$user->scopedCompanyIds(): array
```

- Returns `[]` for admins (`ticket.view.all`) — caller treats as "no filter".
- Returns `[own_company_id]` for normal users (derived from `employee.company_id`).
- Returns `[id1, id2, ...]` for users granted extra access via `user_company_access`.

Pivot table: **`user_company_access`** (`user_id`, `company_id`, `granted_by`,
timestamps; UNIQUE on `(user_id, company_id)`). Eloquent relation:
`$user->extraCompanies()` (BelongsToMany with `granted_by` pivot).

Managed in the panel via the `CompanyAccessRelationManager` on `UserResource`,
gated behind `user.role.assign`.

Usage: `Ticket::scopeVisibleInTeamWorkflow` uses it for `ticket.view.company`.

## SLA Engine & Lifecycle — Phase 2 (branch `faz-2-sla-motoru`)
Requests (`tickets.team_id` set) are driven **only** by
`App\Services\TicketWorkflowService`. Details: `app/Services/CLAUDE.md`.
- SLA clock starts when the ticket reaches the team (open / transfer / reopen),
  in the team's working time (`WorkingTimeCalculator`, holidays included).
- `ticket_sla_cycles` = one row per team arrival (targets + calendar snapshot);
  `ticket_assignments` = who held the ticket when. Handing over never resets SLA.
- Breach attribution (decision 14): holder at the deadline → `person`; holder
  who took over with < 25 % left → `handover` (team); nobody → `dispatch` (team).
- `ProcessTeamTicketSla` (every 5 min): response breach, resolution breach
  (+ `TeamTicketSlaBreached`), 80 % warning once per cycle (+ `TeamTicketSlaWarning`),
  auto-close. The two events have no listeners until the notification phase.

## Known Issues (audit 2026-11-17)
Each open item needs an explicit prompt before it is touched (Altın Kural #4).
1. ✅ **Fixed in Phase 0** — login rate limiting. `AuthRequest` limits failed
   attempts per username+IP (5 / 60 s) and per username across all IPs
   (10 / 15 min, below AD lockout). Checked in `AuthController::login` before
   LDAP is contacted; cleared on success. Tests: `LoginRateLimitTest`.
3. ✅ **Fixed in Phase 0** — SLA warning spam. The warning de-dupe now uses
   `tickets.sla_warning_sent_at` (once per ticket per calendar day), stamped
   before sending. Tests: `SlaWarningDedupTest`. The breach path still uses
   `alreadySentToday` (it flips once, and `sla_breach` is always-on in the bell).
4. **SLA warning fires immediately after reassign/reopen** — the 80% ratio is
   measured from `created_at`, but those paths rebase `sla_deadline` from `now()`.
5. **Performance dashboard**: every query filters `whereBetween('resolved_at', …)`,
   so `currently_open`, `currently_on_hold` and `at_risk` are effectively always 0.
6. **Notification preferences UI is partly inert**: mail toggles have no effect
   (targeted events always mail); `ticket_closed` row matches no notification;
   `ticket_resolved` / `ticket_cancelled` are not configurable.
7. `SubArea::query()` override dereferences `auth()->user()` — throws in
   CLI/queue context if called there.
8. `User::query()` override also hides users whose `username` is `NULL`
   (`NULL != 'sa'` is not true in SQL).
10. `ListTickets` renders 9 tab badges + 2 nav-badge counts, each running
    `visibleBy()` (4–5 queries), re-polled every 60 s; bell polls every 5 s.
11. `ticket_no` = yearly `count()+1` — race-prone under concurrent creates
    (UNIQUE violation), and breaks if rows are ever force-deleted.
12. `UserService::syncFromLdap` stores a bcrypt hash of the user's **AD password**
    in `users.password` on every login.
13. `notifyCreatorOfReassignment` ignores `ticket_mutes` (other targeted rules honour it).
15. 18 `__('ui.*')` keys used in code are missing from `lang/tr/ui.php`
    (e.g. `password_min_length`, `phone_numeric`, `unknown`, `email_invalid`).
